# Geelong Beekeepers Club Newsletter — page-turning reader

A fork of the Australian Bee Journal reader for the GBC newsletter: the same cover-anchored
page stack with live, selectable text over the page art, a rail of titles, authors and topics
beside every page, browse by author or topic ("special issues" assembled from past newsletters),
the bee pointer, and plain-text versions of every item for search engines and screen readers.

Everything is static files. Open `index.html` straight from this folder, or put the folder on any
web host (GitHub Pages works: repository root = this folder).

## Layout

    index.html             the reader (generated by _build/fork_reader.py, data baked in by gbc_articles.py)
    html/<issue>/N.html    one document per newsletter page: background JPEG (text lifted) + positioned live text
    html/<issue>/pgNNN.jpg the page with its text removed
    assets/<issue>/p-NN.jpg whole pages at strip size (covers, past-issue cards, topic lanes)
    assets/gbc_logo.png    the club's masthead, lifted from the newsletter's first page
    article/<slug>/        text version of each item (crawlable, "Read as text")
    article/index.html     every item, by issue
    fonts/                 Lato (open licence) stands in for the website's Proxima Nova
    general/               the General Beekeeping resources collection, same reader (see general/README.md)
    print.html             print view: print.html#/<issue> for a whole issue, #/<issue>/<from>-<to> for an article
    sitemap.xml, robots.txt
    _build/                the build scripts and the article catalogue (ignored by GitHub Pages)

The western edge of the reader (the tab on the left, or the ← key) hands over to
https://geelongbeekeepersclub.org.au/.

## Adding an issue

1. Save the newsletter as a PDF the way these three were (print the eNews page to PDF, A4).
2. Build its pages:

       python _build/gbc_build.py <reader dir> <id> <id> "<Month YYYY>" "<the PDF>"

   e.g. `python _build/gbc_build.py . oct oct "October 2026" "../GBC NEWSLETTER 2026 10 October.pdf"`.
   The script works out which of Chrome's nameless Type3 fonts are the regular, bold, italic and
   bold-italic faces by how they are used, and prints what it decided.
3. Add the issue to `ISSUES` in `_build/fork_reader.py` (id, label, folio text, page count; the last
   one listed is the current issue) and run `python _build/fork_reader.py <path to the ABJ reader> .`
   — or, if the ABJ reader is not to hand, add the issue by hand to `const D=` in index.html.
4. Catalogue the items in `_build/arts.json` (title, first and last page, author, tags), then

       python _build/gbc_articles.py .
       python _build/gbc_toc_links.py .

   The first bakes the records into index.html and writes the text pages, sitemap and article
   index; the second turns the contents-page tiles into in-reader page jumps.

Topic and author lanes can also draw on the General Beekeeping collection and the Australian Bee
Journal; three toggles at the top of a lane switch each collection on or off. The ABJ pages are
expected at `../abj/` (true on krisfricke.github.io).

The Australian Bee Journal collection is currently switched off (`const SHOW_ABJ=false;` in
index.html, general/index.html and _build/fork_reader.py): its toggle is hidden and its articles are
not mixed in. Set it to `true` in all three to bring it back; nothing else needs changing.

Tags roll up automatically: the browse-by-topic panel lists every tag in use, and flowering plants
(the `FLORA` list in index.html) sit together under "Flora". Authors are split on commas and filed
by surname; organisations file under their own first word.

## Editing tags in the browser

Open the reader with `?edit` on the address to reveal Tag mode and Export tags. Changes are kept in
the browser's local storage until exported; paste the exported records into `_build/arts.json` and
rebuild to bake them in.

## Share links

"Share this article" copies the address the item will have once published. That address is set by
`READER_URL` in `_build/fork_reader.py` and `SITE` in `_build/gbc_articles.py`; both are placeholders
(`https://krisfricke.github.io/gbc/`) until the reader has a home.
